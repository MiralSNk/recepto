# Настройка Yandex Cloud: API-ключи для чата и капчи

Сайту нужны 4 значения из [console.yandex.cloud](https://console.yandex.cloud) — они идут в `.env.production` (или `.env.local` для разработки):

| Переменная | За что отвечает |
|---|---|
| `YANDEX_FOLDER_ID` | ID каталога (folder) — нужен для запросов к YandexGPT |
| `YANDEX_API_KEY` | Ключ сервисного аккаунта — авторизация запросов к YandexGPT |
| `YANDEX_CAPTCHA_SERVERKEY` | Серверный ключ SmartCaptcha — проверка ответа пользователя на бэкенде |
| `NEXT_PUBLIC_YANDEX_CAPTCHA_SITEKEY` | Клиентский ключ SmartCaptcha — показ виджета в браузере |

Ниже — как получить каждое, с нюансами, которые не всегда очевидны из интерфейса.

## Перед началом: платёжный аккаунт

Yandex Cloud даёт попробовать YandexGPT прямо в консоли без привязки карты (лимит — около 10 бесплатных запросов в час), но **API для сайта требует привязанного платёжного аккаунта** — без него ключ создать можно, а вот реальные запросы будут отклоняться. Привязка — в консоли, слева «Биллинг» → «Привязать платёжный аккаунт». Есть регулярные грантовые программы Yandex Cloud (стартовые гранты/промокоды на пробный период) — стоит проверить перед тем, как вносить карту.

## YandexGPT: `YANDEX_FOLDER_ID` и `YANDEX_API_KEY`

Yandex в 2025–2026 перевёл интерфейс работы с моделями на новый продукт **AI Studio** — старые ссылки на «Foundation Models» в документации теперь ведут туда же. Практический эффект: создавать ключ проще, чем раньше.

### Быстрый способ (рекомендован самим Yandex)

1. Откройте [aistudio.yandex.cloud/platform](https://aistudio.yandex.cloud/platform/).
2. Нажмите **«Создать API-ключ»** в правом верхнем углу.
3. При желании измените описание ключа и срок действия, нажмите **«Создать»**.
4. Сохраните выданный ключ **сразу** — повторно посмотреть его будет нельзя, только пересоздать.

AI Studio сам создаст сервисный аккаунт с нужными правами — вручную назначать роли не придётся.

### Ручной способ (если нужен отдельный сервисный аккаунт с ограниченными правами)

1. В консоли (console.yandex.cloud) выберите каталог (folder), в котором должен жить сервисный аккаунт.
2. «Сервисные аккаунты» → «Создать сервисный аккаунт».
3. Назначьте роль **`ai.languageModels.user`** (минимально достаточная — только вызов моделей, без доступа к остальным сервисам каталога).
4. Откройте созданный аккаунт → вкладка «API-ключи» → «Создать API-ключ» (не путать с IAM-токеном — токен истекает через 12 часов, API-ключ бессрочный и проще в проде).

### Где взять `YANDEX_FOLDER_ID`

Это ID каталога (не аккаунта и не облака целиком) — того самого, где создан сервисный аккаунт. В консоли: выберите каталог в списке слева, ID показан прямо на странице каталога либо в адресной строке. Приложение подставляет его в `modelUri: gpt://<folder_id>/yandexgpt-lite` и в заголовок `x-folder-id` при каждом запросе — если каталог укажете не тот, где выпущен ключ, запросы будут падать с ошибкой доступа, даже если сам ключ рабочий.

## SmartCaptcha: серверный и клиентский ключи

1. В консоли — «Все сервисы» → раздел «Безопасность» → **Yandex SmartCaptcha**.
2. «Создать капчу», задайте имя.
3. **Обязательно** заполните поле со списком доменов сайта (например `your-domain.ru`, а на разработке дополнительно `localhost`) — это и есть тот самый нюанс.
4. Настройте сложность (по умолчанию «Средняя» подходит для большинства сайтов), сохраните.
5. Откройте созданную капчу — там два ключа: клиентский (`NEXT_PUBLIC_YANDEX_CAPTCHA_SITEKEY`) и серверный (`YANDEX_CAPTCHA_SERVERKEY`).

### Почему домен обязателен

Если домен сайта не добавлен в список (или добавлен с опечаткой, другим поддоменом, http вместо https и т.д.) — **виджет капчи просто не появится на странице**, без ошибки в консоли Yandex Cloud и часто без явной ошибки в консоли браузера. Выглядит так, будто сломался сам сайт или код капчи, хотя причина — несовпадение домена в настройках капчи. Если меняете домен сайта (например, после переезда на новый сервер) — не забудьте обновить список доменов в настройках капчи, иначе форма бронирования молча перестанет показывать капчу и её проверка на бэкенде будет всегда отклонять отправку.

Для локальной разработки (`localhost:3000`) добавьте `localhost` отдельной строкой в тот же список — капча одна и та же что на проде, что локально, домены просто перечисляются через запятую/с новой строки в её настройках.
